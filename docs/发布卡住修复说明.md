# 「正在发布」一直转圈：更新与排查

旧版没有对本地图片读取和云调用增加独立超时保护：底层接口迟迟不返回时，页面会一直等待。仅凭转圈还不能确定真实云环境的问题发生在哪一步。新版补上分步提示、超时退出以及云端分阶段日志，用于恢复操作并定位故障。

## 更新现有项目

如果你正在微信开发者工具中使用另外一份项目，可使用 `artifacts/wechat-publish-fix.zip`。把压缩包中的 `miniprogram`、`cloudfunctions` 目录合并覆盖到**正在用的项目根目录**，不要只解压在一个无关的新文件夹中。

修复包只包含以下 6 个代码文件以及本说明：

```text
miniprogram/utils/api.js
miniprogram/pages/admin/admin.js
miniprogram/pages/admin/admin.wxml
miniprogram/pages/admin/admin.wxss
cloudfunctions/imageBoard/index.js
cloudfunctions/imageBoard/service.js
```

包内没有 `project.config.json`、`miniprogram/config.js`，因此不会覆盖你填写的 AppID 和环境 ID。

1. 覆盖这 6 个文件。如果正在使用本次修改的同一目录，则无需复制。
2. 在开发者工具右键 `cloudfunctions/imageBoard`，选择「上传并部署：云端安装依赖」。仅点击编译不能更新云函数。
3. 在云开发控制台确认 `imageBoard` 超时时间为 **60 秒**，核对 `ADMIN_OPENIDS` 环境变量仍保留且生效。
4. 回到开发者工具点击「编译」。如果在手机上测试，重新点击「预览」并扫码，或更新体验版后重新进入，确保加载新版代码。
5. 进入管理页，先用一张较小的 JPG / PNG 图片测试发布。图片上限仍为 2MB，支持格式不变。

这次无需重建数据库、重置 `current` 记录或修改数据库 / 云存储权限。

## 新版等待上限

| 阶段 | 最长等待 | 超时后的行为 |
| --- | --- | --- |
| 用户确认框 | 等用户确认或取消 | 不因用户思考时间长而自动发布 |
| 读取本地图片 | 10 秒 | 退出加载，提示重新选择图片，不提交发布 |
| 发送图片并等待云函数发布结果 | 45 秒 | 退出发布遮罩，保留结果未确认提示，不自动重试 |
| 刷新确认当前图片 | 20 秒 | 恢复按钮，查询失败则要求重新加载确认后再发布 |

云函数内部还分别限制数据库读取 8 秒、存储上传 20 秒、数据库提交 8 秒、图片访问链接获取 8 秒。平台自身配置的超时也会生效；若配置比代码内上限短，平台可能先结束调用。

超时只表示结束等待，不代表撤销底层云操作。数据库提交有可能在响应超时后完成，因此程序不会自动重试，也不会在结果不确定时删除图片。

## 根据提示排查

| 提示 / 错误码 | 检查方向 |
| --- | --- |
| `READ_TIMEOUT` | 本地图片读取未返回，重新选择一张小图，必要时用手机真机重新预览 |
| `CLIENT_TIMEOUT` | 客户端没有按时拿到云调用响应；检查网络、函数是否执行及日志，不代表发布必然失败 |
| `FUNCTION_TIMEOUT` | 平台返回了云函数超时；检查函数的 60 秒超时配置以及具体执行日志 |
| `DATABASE_TIMEOUT` | 云函数等待数据库读取超时；检查环境状态及数据库服务 |
| `UPLOAD_TIMEOUT` / `UPLOAD_FAILED` | 云函数上传到云存储未完成 / 失败；重点看 `storage.upload` 的日志和 SDK 错误 |
| `COMMIT_UNCERTAIN` | 保存记录的结果不确定；先刷新 `current` 记录确认是否已经发布成功 |
| `IMAGE_TIMEOUT` | 已发布图片访问链接获取超时；检查云存储状态与 `storage.url` 日志 |

## 云端日志在哪里看

打开云开发控制台 → 云函数 → `imageBoard` → 日志，找刚才点击发布对应的调用记录。新版会记录：

```text
action: publish, stage: database.read, status: start / ok / failed
action: publish, stage: storage.upload, status: start / ok / failed
action: publish, stage: database.commit, status: start / ok / failed
```

刷新图片时还会出现 `action: getCurrent` 和 `stage: storage.url`。按 `action` 和 `requestID` 区分不同请求，检查失败阶段的 `code`、`message` 及耗时；平台也可能直接记录函数超时错误。

若仍然发布失败，提供页面上的错误文字或 `publish` 对应的失败日志即可继续定位。不需要提供图片 Base64、AppSecret、云密钥；代码没有把图片内容写入诊断日志。

## 已验证的范围

自动化测试模拟了本地读取不回调、云调用不回调、发布后查询不回调、云端上传 / 提交超时、提交迟到成功以及迟到回调。页面能退出等待、保留诊断信息，且不会自动重复发布或误删已提交的图片。

这些是模拟验证；你的真实云环境仍需重新部署后验收，不能据此判定真实云端发布故障已经消失。
