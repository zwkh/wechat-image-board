# 原生上传修复版：更新与日志说明

本版把图片改为 `wx.cloud.uploadFile` 原生文件上传，发布函数只接收 `fileID` 和版本号。此前通过云函数参数传递整张图片的 Base64，现在避开这条大参数路径。已有日志能确认小请求及数据库读取正常，尚不能仅凭 CLIENT_TIMEOUT 判定真实传输故障的具体原因；新版仍需部署后真机验收。

## 一、更新正在使用的项目

源码已直接修改在本项目目录中。优先让微信开发者工具打开这个源码目录，再编译和部署云函数，不需要下载或解压任何包。用 Git 查看修改和记录版本。

如果微信开发者工具实际打开的是另一个目录，应先核对该目录，并在确定的项目中同步源码、保留已填写的 AppID 和环境 ID。`artifacts/wechat-native-upload-fix.zip` 只是供跨目录或跨电脑手动同步的可选副本，不是更新的必经步骤。

修复包不含 `project.config.json`、`miniprogram/config.js`，不会覆盖 AppID 和环境 ID。前端与云函数必须一起更新，不能只编译旧代码或只更新一端。

1. 确认微信开发者工具打开的是已更新的源码目录；只有使用另一份项目时才需要同步代码。
2. 右键 `cloudfunctions/imageBoard` → 上传并部署：云端安装依赖。
3. 云函数超时时间保持 60 秒，核对 `ADMIN_OPENIDS` 保留并生效。
4. 重新编译，在管理页重新验证管理员身份。
5. 点击管理页「首次部署：复制我的云存储权限规则」。
6. 打开云开发控制台 → 云存储 → 权限设置 → 自定义安全规则，粘贴并保存。数据库权限不变。
7. 等待规则生效，重新选择图片并发布。手机测试请重新预览扫码或更新体验版。

## 二、云存储规则是必做配置

旧版存储权限为客户端全部禁写，原生上传也会被它拒绝。新版改为仅指定管理员 OpenID 可以写 uploads 目录：

```json
{
  "read": false,
  "write": "auth.openid == '你的管理员OpenID' && /^uploads\\//.test(resource.path)"
}
```

推荐用管理页复制按钮自动填入真实 OpenID，避免手动漏字符。模板也在 `deploy/storage.rules.json`，使用模板时必须替换占位值。

- 普通用户仍不能上传、更改或删除图片。
- 云函数在发布时再次核验管理员身份、云环境、文件所属目录、实际文件大小及格式。
- 数据库保持 `{ "read": false, "write": false }`，不需要重建记录。
- 更换管理员时，同时更新 `ADMIN_OPENIDS` 和云存储规则。不要将 write 设置为 true。

## 三、为什么日志看起来很多

`imageBoard` 是统一入口，承担不同操作，并非每条调用都在发布：

| 操作 | 调用 |
| --- | --- |
| 打开或返回展示页 | getCurrent 一次 |
| 进入或重新加载管理页 | identity 一次；管理员随后 getCurrent 一次 |
| 选择图片、取消确认框 | 不调用发布函数 |
| 确认发布 | 原生上传文件；成功后 publish 一次；随后 getCurrent 一次确认结果 |
| 发布超时或失败 | 如已发送 publish，会 getCurrent 一次确认；不自动重试发布 |

同一个 RequestId 的 START、Event、业务阶段日志、Response、END、Report 属于同一次执行。Init Report 和 Report 如果 RequestId 相同，也不是两次调用。不同 RequestId 才是不同请求。

此版本没有定时轮询或无限循环重试。单看函数执行状态 200 还不能判断图片发布成功，应展开记录查看 action 和返回结果。

## 四、等待上限与错误定位

| 阶段 | 等待上限 | 错误码及处理 |
| --- | --- | --- |
| 原生文件上传 | 60 秒 | UPLOAD_TIMEOUT：检查网络；STORAGE_PERMISSION：更新上述存储规则 |
| 发布云函数 | 45 秒 | CLIENT_TIMEOUT：未收到结果，刷新确认；查看该次 publish 的云日志 |
| 云端读取已上传文件 | 20 秒 | FILE_TIMEOUT / FILE_UNAVAILABLE：检查云存储及 storage.download 日志 |
| 云端数据库读写 | 每步 8 秒 | DATABASE_TIMEOUT / COMMIT_UNCERTAIN：按日志检查，先确认是否已提交 |
| 随后刷新当前图片 | 20 秒 | 失败后解锁，重新加载确认结果后再发布 |

新版发布请求没有 Base64 图片参数，正常会出现：

```text
action: publish, stage: database.read, status: start / ok / failed
action: publish, stage: storage.download, status: start / ok / failed
action: publish, stage: database.commit, status: start / ok / failed
```

客户端文件上传不属于云函数执行，因此上传本身没有 publish 的云函数日志。上传失败时会直接提示，不继续提交发布。

如果返回 INVALID_FILE，请确认两端都已更新，文件 ID 属于当前环境及当前管理员的 uploads 目录。之前传空 imageBase64 的旧版诊断脚本不再适用于本版。

超时只表示停止等待，不代表底层操作一定撤销。程序不会在结果不确定时自动重复发布或删除图片；失败上传及历史文件可按部署指南定期清理。

## 五、验证范围

自动化测试覆盖原生上传流程、发布参数不含 Base64、权限拒绝、其他环境及他人文件拒绝、文件大小 / 格式复核、并发提交、超时、迟到结果以及当前图片刷新。模拟测试不能替代真实微信及云环境验收。

官方参考：[原生上传 API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.cloud.d.ts)、[云存储安全规则](https://docs.cloudbase.net/en/storage/security-rules)。
