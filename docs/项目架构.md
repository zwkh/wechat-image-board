# 项目架构与维护说明

本文对应 `D:\wechat-image-board` 当前源码，整理于 2026-10-25。操作步骤见[部署指南](部署指南.md)。本项目展示一张统一发布的图片；普通用户看图，业务管理员换图。

## 1. 整体组成

```text
普通微信用户
  → 小程序展示页 → imageBoard(getCurrent)
                    → 数据库 image_board/current：读取当前 fileID
                    → 云存储：生成临时访问链接 → 页面加载图片

管理员微信
  → 小程序管理页 → imageBoard(identity)：核验管理员身份
  → 选择本地图片 → 确认 → wx.cloud.uploadFile：上传到云存储
  → imageBoard(publish)：校验身份、文件、版本
                    → 更新 image_board/current → 用户刷新后看到新图
```

前端是微信原生小程序，没有独立的网站管理后台。管理页也运行在微信中；可信的权限判断与数据库操作在云函数中。云数据库和云存储是两个服务，不是同一个地方。

## 3. 云数据库到底存什么

当前程序使用集合 **`image_board`**，只读写其中 **`_id = current`** 的一条记录，不会每上传一张图就新增一条数据库记录。

首次初始化：

```json
{ "_id": "current", "version": 0 }
```

发布后的结构示意（值仅为示例，不要导入覆盖现有数据）：

```json
{
  "_id": "current",
  "fileID": "cloud://example-env.example-bucket/uploads/example-openid/1234567890-abc.png",
  "updatedAt": 1792900000000,
  "version": 2
}
```

| 字段 | 含义 |
| --- | --- |
| `_id` | 固定为 `current`，代表当前公开展示内容 |
| `fileID` | 云存储中当前图片的文件标识，不是图片二进制或 Base64 |
| `updatedAt` | 服务端生成的毫秒时间戳，页面转换成北京时间 |
| `version` | 图片内容版本，每次成功发布加 1，用来防止并发覆盖；与小程序代码版本 `1.0.0` 无关 |

返回给页面的 `imageUrl` 是云函数根据 `fileID` 临时生成的访问链接，不是数据库保存的字段。链接可能过期，页面重新请求时会重新获取。

当前没有图片历史记录表、发布审计表、用户资料表或数据库管理员表。管理员名单在云函数环境变量 `ADMIN_OPENIDS` 中。旧文件路径虽包含上传者 OpenID，但这不是完整审计记录，也没有历史版本自动回退功能。

## 4. 每张图片都会保存吗

| 操作 / 结果 | 云存储 | 数据库当前记录 |
| --- | --- | --- |
| 仅选择图片、查看本地预览、取消确认 | 不上传 | 不变 |
| 确认后上传成功，发布也成功 | 新增图片文件 | 改为新 fileID，更新时间，版本加 1 |
| 上传成功，但发布被拒绝或发生版本冲突 | 新文件仍保留 | 此次操作不会更新当前记录 |
| 网络超时、结果未确认 | 可能已经存在文件 | 可能已提交，必须重新查询判断 |
| 再次成功换图 | 新旧图片都保留 | 只指向最新图片 |

每次上传使用 `uploads/<OpenID>/<时间戳>-<随机值>.<扩展名>`，重复发布同一张原图也会生成新文件，不做去重。现有代码没有自动删除逻辑，所以云存储可能积累已发布的旧图和上传成功但未发布的文件；数据库仍只维护一条当前记录。

例如依次成功发布 A、B、C，数据库只指向 C，云存储保留 A、B、C。只看数据库不能找到 A、B 的完整发布历史。

清理时先暂停发布，查出当前 `fileID`，保留该文件及近期可能仍被打开页面使用的旧文件，核对后再删历史文件。不能清空整个目录。历史实现可能在 `published/` 留有文件，也应逐个确认。需要回退时重新选择旧原图发布，生成新的版本。详见部署指南第十一节。

## 5. 接口与发布过程

所有业务调用都使用云函数 `imageBoard`，通过 `action` 区分：

| action | 调用者 | 输入 | 成功返回 data |
| --- | --- | --- | --- |
| `identity` | 有微信身份的小程序用户 | 无额外业务参数 | `openid`、`isAdmin` |
| `getCurrent` | 有微信身份的小程序用户 | 无额外业务参数 | `imageUrl`、`updatedAt`、`version` |
| `publish` | `ADMIN_OPENIDS` 中的管理员 | `fileID`、`expectedVersion` | 新 `version`、`updatedAt` |

成功统一返回 `{ ok: true, data }`，失败返回 `{ ok: false, code, stage, requestID, message }`。云函数运行状态为 200 不必然代表业务发布成功，还要看 `ok` 与 `action`。

发布时，服务端先验证微信身份在管理员名单中，再检查当前版本、fileID 所在环境和本人上传目录，下载实际文件校验大小与文件头。目前限制 2MB、JPG / PNG / WebP；文件头检查不等于完整图片解码或内容审核。最后按旧版本条件原子更新数据库，避免两个管理员同时发布时互相覆盖。

上传与数据库写入不是一个跨服务事务，因此存在“文件上传了但没发布”的情况。发布请求失败或超时后前端查询当前内容确认，不自动重发，也不直接删除可能已成为当前图片的文件。

首页进入 / 再次显示、下拉刷新会读取最新内容；没有持续轮询或实时推送。管理页检查身份、读取当前内容、发布后确认也会产生调用，因此一次操作可能有多条不同请求日志。`START`、`Event`、阶段日志、`END`、`Report` 也可能属于同一个 RequestId，应按 RequestId 和 action 区分，不能按日志行数算调用次数。

## 6. 身份与权限边界

普通用户在现有界面只能看图，没有上传发布按钮；即使直接调用 `publish`，服务端也会拒绝非管理员。这与“底层存储是否允许某个客户端另行上传文件”是两件事。

| 配置 | 作用 |
| --- | --- |
| 微信公众平台开发者 / 体验成员 | 决定能否开发、上传代码或打开体验版；不自动获得业务发布权限 |
| 云函数 `ADMIN_OPENIDS` | 决定哪些微信身份可以发布当前图片；支持英文逗号分隔多人 |
| 数据库仅管理端可读写 | 客户端不能直接改当前记录，统一经过云函数 |
| 云存储仅创建者可读写 | 以每个文件的创建者为权限依据，不等于仅小程序业务管理员能上传 |
| 云存储自定义规则 | 环境支持时，可额外限定管理员的客户端上传权限 |

当前用户反馈试用环境不能设置自定义规则，因此暂沿用“仅创建者可读写”。这不增加普通用户的界面功能，也不使其获得发布权限；但不能据此宣称存储层只允许 `ADMIN_OPENIDS` 中的人上传。服务端生成当前图片临时链接供用户查看，仍须以另一个微信账号真机验收读取链路。[云存储基础权限官方说明](https://docs.cloudbase.net/storage/data-permission)。

当前管理页复制的自定义规则只包含当前一个 OpenID，多管理员不能各自复制覆盖同一份规则，否则会挤掉其他管理员。环境支持自定义规则时须维护包含所有管理员的规则；不支持时，严格限制上传需要可用的权限能力或另外开发服务端鉴权上传方案，当前代码未实现后一方案。不要将现有原生上传所需的客户端写入全部禁用后期待它仍能工作。

## 7. 配置、部署与版本关系

| 改动 | 生效方式 |
| --- | --- |
| 选图并发布内容 | 管理页操作，更新云数据；无需重发小程序代码 |
| 修改 `miniprogram/` 页面、标题、环境 ID | 本地编译验证；对外需上传代码、审核、发布 |
| 修改云函数代码 / 依赖 | 单独上传部署 `imageBoard`，不会随小程序代码上传自动部署 |
| 修改 `ADMIN_OPENIDS` | 云函数配置保存生效，必要时按控制台要求更新配置 |
| 数据库 / 存储规则 | 云控制台保存生效，不是只修改本地 JSON |

开发版、体验版和正式版若使用同一云环境，就共用同一条 `current` 记录和云函数。**体验版管理员换图也会影响正式版用户**。要隔离测试数据，需独立测试环境并分别初始化函数、数据和权限；当前项目不会自动按版本切换环境。

源码使用 Git 管理，但 Git 不备份云数据库、云存储和云端环境变量。维护只操作 D 盘项目，不通过压缩包或旧 C 盘副本同步。具体体验版和正式版步骤见[部署指南第九节](部署指南.md#九体验版与正式版发布)。

## 8. 排查与验证

客户端等待上限：上传 60 秒、发布调用 45 秒、查询 20 秒。服务端阶段上限：读数据库 8 秒、下载文件 20 秒、提交记录 8 秒、取临时链接 8 秒。超时停止等待，不保证底层操作被撤销。

| 观察点 | 如何判断 |
| --- | --- |
| 上传进度 / `UPLOAD_TIMEOUT` | 查客户端网络、存储权限和文件是否已落入云存储 |
| `identity` / `FORBIDDEN` | 查实际手机 OpenID 与云端管理员名单 |
| `database.read` | 查环境、集合名、`current` 和数字 version |
| `storage.download` | 查 fileID、实际文件、环境与本人目录 |
| `database.commit` | 查版本冲突或提交结果未确认，重新查询当前记录 |
| `storage.url` | 查当前文件是否存在、临时链接生成结果 |

过去提供的 `getCurrent` 日志只证明读请求成功，不能证明 `publish` 执行过；空图片请求返回 `INVALID_IMAGE` 也不等于真实图片上传链路成功。不能只凭这些日志认定原先超时一定由大小限制或数据库权限导致。

本地检查（在项目根目录执行）：

```powershell
node scripts/check.js
node --test tests/api.test.js tests/frontend.test.js tests/service.test.js
```

自动化测试模拟云服务，不能替代真实云权限、不同微信账号和手机验收。上线前按部署指南第八节测试管理员发布、普通用户读取、换图刷新和拒绝越权。本文是源码架构说明，不表示已替用户完成体验版上传、审核或正式发布。
