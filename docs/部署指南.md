# 部署指南

目标：先在自己的微信上预览成功，再提交审核公开发布。所有 AppID、环境 ID、集合和云函数都必须属于同一个小程序及其关联的云环境。

## 一、准备小程序账号与工具

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，注册账号时选择「小程序」。已经有小程序账号可直接使用。
2. 登录小程序管理后台，完善名称、头像、简介、服务类目等资料。根据实际展示内容选择合适的类目，按后台提示准备所需资质。
3. 找到「开发管理 → 开发设置」一类入口，复制 **AppID**，通常以 `wx` 开头。这里不需要把 AppSecret 填到代码中。
4. 从[官方入口](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装微信开发者工具稳定版，使用小程序管理员或已添加的开发者微信扫码登录。
5. 如由其他微信预览，请在公众平台「成员管理」中按用途添加项目成员或体验成员。

**注意：测试号、游客模式不能代替真正账号完成本文云开发部署。** 项目中的 `touristappid` 只是占位值。

## 二、导入项目

1. 开发者工具选择「导入项目」。
2. 目录选择本项目的根目录，即包含 `project.config.json` 的文件夹。不要只选择 `miniprogram` 子文件夹。
3. 填写你的 AppID，项目名称可自定。如果出现后端服务选项，选择「微信云开发」。不需要覆盖本项目或生成模板。
4. 核对 `project.config.json` 的 `appid` 已变为你的真实 AppID。
5. 项目配置已指定 `miniprogramRoot: miniprogram/` 和 `cloudfunctionRoot: cloudfunctions/`，正常会显示这两个目录。

建议调试基础库选开发者工具当前支持的稳定版本，至少支持 `wx.chooseMedia`。本项目没有小程序端 npm 依赖，不需要执行「构建 npm」。

## 三、开通云开发环境

1. 点击开发者工具顶部「云开发」，按提示开通并创建环境。
2. 本项目使用微信 `wx.cloud` 接入及**文档型 / NoSQL 数据库**。如果账号提供多种数据库模式，请选兼容该数据库 API 的环境，不要直接改用 PostgreSQL。
3. 复制完整的**环境 ID**，不是显示名称。
4. 编辑 `miniprogram/config.js`：

```javascript
module.exports = {
  envId: '你的真实云环境ID',
  title: '最新图片'
};
```

5. 在 `cloudfunctions` 目录的右键菜单中，如有「当前环境」，选中同一个环境。

开通前查看控制台实际套餐和计费说明，按需要设置费用提醒。这里不承诺免费额度或固定月费。

## 四、初始化数据库并配置权限

### 4.1 创建集合与记录

进入云开发控制台 → 数据库，创建集合：

```text
image_board
```

在集合中「添加记录」，切换到 JSON 模式，粘贴以下内容并保存（同样内容位于 `deploy/initial-record.json`）：

```json
{
  "_id": "current",
  "fileID": "",
  "updatedAt": null,
  "version": 0
}
```

`version` 必须是数字，`_id` 必须是 `current`。这条记录只在首次部署时创建，日常换图不要重置它。

### 4.2 数据库权限

将 `image_board` 集合设置为**仅管理端可读写**。若使用自定义安全规则，粘贴：

```json
{ "read": false, "write": false }
```

模板在 `deploy/database.rules.json`。这里的「管理端」指云函数 / 控制台，不是客户端管理页面。小程序的所有读写都通过云函数执行。

### 4.3 云存储权限

进入云开发控制台 → 云存储 → 权限设置，同样设置为**仅管理端可读写**，或使用：

```json
{ "read": false, "write": false }
```

模板在 `deploy/storage.rules.json`。云函数负责上传，并为当前图片生成访问链接。普通微信用户不需要直接拥有云存储读写权限。

修改规则后等待生效再验收。请勿为解决报错把数据库或存储改成「所有人可写」。[官方存储规则说明](https://docs.cloudbase.net/en/storage/security-rules)指出客户端规则不会限制服务端 SDK，规则变更可能需要 1–3 分钟生效。

## 五、部署云函数

1. 在左侧文件树展开 `cloudfunctions`。
2. 右键 **`imageBoard`**，选择「上传并部署：云端安装依赖（不上传 node_modules）」或同义入口。函数名要保持为 `imageBoard`。
3. 等待依赖安装和部署成功。函数使用固定版本 `wx-server-sdk@4.0.2`，无需在本机安装 npm。
4. 进入云开发控制台 → 云函数 → `imageBoard` → 配置，将超时时间设为 **60 秒**，内存可从 **256MB** 开始。运行时选择控制台支持的 Node.js 稳定版本，建议 Node.js 18 或更高。
5. 如果控制台提供云函数调用权限，保留允许本小程序微信身份调用的设置。发布操作还会在函数内部核验管理员身份，不能把整个函数设为「只有云控制台管理员可调用」，否则普通用户也无法看图。
6. 本项目通过小程序 `wx.cloud.callFunction` 调用，无需开启 HTTP 访问或配置 HTTP 触发器。

不要把 `ADMIN_OPENIDS` 写在前端页面或 `miniprogram/config.js`。下一步将在云端配置。

## 六、绑定你自己的微信为管理员

1. 点击开发者工具「编译」。首页此时应显示「图片即将发布」。
2. 点击「预览」，用你以后要管理图片的微信扫码，在**手机真机**中打开。
3. 点击首页底部「管理入口」。首次会显示「当前微信没有发布权限」。这是预期行为。
4. 点击「复制我的 OpenID」。这个标识对应**当前微信在这个小程序中的身份**，不是微信号，也不是 AppID。
5. 回到电脑，打开云开发控制台 → 云函数 → `imageBoard` → 配置 / 环境变量，新增：

| 变量名 | 变量值 |
| --- | --- |
| `ADMIN_OPENIDS` | 第 4 步复制的完整 OpenID |

6. 保存配置，按界面提示使配置生效。如果工具要求更新函数，则重新部署并核对环境变量仍保留。
7. 手机管理页点击「重新验证权限」。现在应显示「已验证 · 管理员」和选图、发布按钮。

需求是只有你有修改权限，所以默认只填你自己的一个 OpenID。以后确需多个管理员，值可用英文逗号分隔：`openidA,openidB`。移除某个 OpenID 并使配置生效后，该微信就不能继续发布；服务端每次发布都会重新校验身份。

如果拿开发者工具模拟器复制的 OpenID，务必核对它和实际管理用手机页面显示的一致。发布权限不自动等于微信公众平台里的「管理员」角色，而是由这里的名单明确指定。

## 七、发布第一张图片

1. 管理页点击「从相册或相机选择」，选择 JPG / PNG / WebP，文件不超过 **2MB**。
2. 检查预览图片。选图本身不会改变用户当前看到的内容。
3. 点击「确认并发布」，在确认框中点击「确认发布」。
4. 等待提示「发布成功」，核对「当前发布」区域的新图与更新时间。
5. 点击「返回展示页」，应显示同一张图片及北京时间。

大图请先压缩，HEIC / GIF 等请先转换为受支持的静态图片。如果微信提示隐私或相册 / 相机权限问题，先按提示授权并检查小程序后台的实际隐私接口声明。

如果显示连接异常或「发布结果暂未确认」，先刷新当前图片和版本确认是否已经成功。网络超时并不必然表示发布失败，程序不会自动重复提交。

## 八、真机验收

用自己的微信和另一个已添加为体验成员的普通微信各验收一次：

- [ ] 自己能进入管理页面，普通微信只能看到无发布权限提示。
- [ ] 自己发布图片 A，普通微信打开首页能看到 A 和最后更新时间。
- [ ] 自己替换成图片 B，普通微信下拉刷新能看到 B。
- [ ] 普通微信退出后重新打开、或从后台切回展示页，能获取 B。
- [ ] 点击图片可放大，长图按宽度完整展示，不强制裁剪。
- [ ] 断网加载会显示失败和重试，不把旧图标成最新。
- [ ] 数据库和云存储的客户端直写均被拒绝。
- [ ] 即使普通微信直接调用 `publish`，云函数返回 `FORBIDDEN`，不会上传或修改图片。

开发者工具控制台可用以下只读检查验证当前身份：

```javascript
wx.cloud.callFunction({
  name: 'imageBoard',
  data: { action: 'identity' }
}).then(console.log);
```

普通微信的拒绝测试可用下列代码：服务端应先校验身份，返回 `FORBIDDEN`。

```javascript
wx.cloud.callFunction({
  name: 'imageBoard',
  data: { action: 'publish', expectedVersion: 0, imageBase64: '' }
}).then(console.log);
```

这些调用必须在该微信登录的真实小程序环境中执行，不要用云控制台手动伪造身份验收。

## 九、上线给所有用户

1. 登录微信公众平台，按账号后台要求完善基础资料、服务类目、资质、备案及隐私保护指引。后台管理功能使用图片选择 / 相机相关能力，按实际调用和后台检测结果填写用途，不收集用户昵称、头像、手机号。
2. 在开发者工具点击「上传」，填写版本号（如 `1.0.0`）和说明。
3. 到公众平台的版本管理中，把开发版本设为体验版进行最后检查。
4. 提交审核，按实际功能提供审核说明；用户展示页无需额外账号密码，后台为指定微信管理员功能。
5. 审核通过后，在公众平台点击发布。
6. 下载正式版小程序码，扫码验证线上展示及管理员权限。

这里无法代替你完成账号注册、扫码、主体核验、备案和平台审核；项目也尚未上传到你的账号。具体审核条件和入口以公众平台实时提示为准。

**之后换图片：** 手机小程序 → 管理入口 → 选图 → 发布即可。修改图片不会改动小程序代码包，通常不需要为每次换图重新提交代码审核；展示内容仍应遵守平台要求。

## 十、常见问题

| 现象 | 优先检查 |
| --- | --- |
| 提示填写环境 ID | 修改 `miniprogram/config.js`，填完整环境 ID 后重新编译 |
| 云函数找不到 / 连接失败 | AppID、环境 ID、`cloudfunctions` 当前环境和函数部署目标是否一致，函数名是否为 `imageBoard` |
| 提示创建初始记录 | 集合是否叫 `image_board`，是否有 `_id: current` 的记录 |
| 发布提示版本无效 | `version` 是否是数字，是否误改了初始记录 |
| 本人没有发布权限 | 手机当前 OpenID 是否与云函数环境变量一致，配置是否生效，是否填到了错误环境 |
| 普通用户也无法看图 | 云函数调用权限是否允许本小程序用户，是否误把函数调用权限设为仅管理端 |
| 图片不可访问 | 当前记录的 fileID 对应文件是否还存在，函数是否在正确云环境中生成链接；看云函数日志 |
| 选图失败 | 检查真实文件格式、2MB 限制、微信版本、隐私授权及手机相册 / 相机权限 |
| 上传超时 | 先刷新确认发布结果，再检查网络、函数超时时间和日志；较大图片先压缩 |
| 提示图片已被更新 | 同一时间有另一个发布操作成功。刷新确认最新图片，再重新选图发布 |
| 换图后用户停留页面没变 | 下拉刷新，或离开并重新进入展示页；此版本未做持续实时推送 |
| 本地没有 npm | 直接使用微信工具「云端安装依赖」；本地测试只需要 Node.js |

## 十一、维护、清理与回退

### 旧文件与费用

每次成功发布都会保存一个新的 `published/` 文件，旧文件不会立即删除。这能保证正在读取旧图片的用户不因换图突然失败，但长期更新会占用存储。

建议低频手动清理：先从数据库 `image_board/current` 复制当前 `fileID`，再到云存储确认文件；**保留当前 fileID 对应文件及最近一段时间的旧文件**，只删除已确认不再引用的历史文件。清理过程中先暂停人工发布操作，并在删除前再次核对当前记录。不要清空整个 `published/` 目录。

失败或结果不确定的上传也可能遗留文件，可按同样方式核对。控制台设置费用提醒，关注图片访问流量、函数调用和存储用量，具体价格看当前账号计费页。

### 回退图片

日常回退最简单的做法：管理员重新选择之前的原图并发布。系统会生成新的版本和更新时间，不必手动改数据库。
