# 部署指南

目标：先在自己的微信上预览成功，再提交审核公开发布。所有 AppID、环境 ID、集合和云函数都必须属于同一个小程序及其关联的云环境。

## 一、准备小程序账号与工具

1. 打开 [微信公众平台](https://mp.weixin.qq.com/)，注册账号时选择「小程序」。已经有小程序账号可直接使用。
2. 登录小程序管理后台，完善名称、头像、简介、服务类目等资料。根据实际展示内容选择合适的类目，按后台提示准备所需资质。
3. 找到「开发管理 → 开发设置」一类入口，复制 **AppID**，通常以 `wx` 开头。这里不需要把 AppSecret 填到代码中。
4. 从[官方入口](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装微信开发者工具稳定版，使用小程序管理员或已添加的开发者微信扫码登录。
5. 如由其他微信预览，请在公众平台「成员管理」中按用途添加项目成员或体验成员。

**注意：测试号、游客模式不能代替正式小程序账号完成对外发布。** 本项目已保留用户的 AppID 和云环境 ID，无需重新填占位值；账号类型、发布资格以公众平台为准。

## 二、导入项目

1. 开发者工具选择「导入项目」。
2. 目录选择 **`D:\wechat-image-board`**，即包含 `project.config.json` 的文件夹。不要选择旧 C 盘副本或只选择 `miniprogram` 子文件夹。
3. 填写你的 AppID，项目名称可自定。如果出现后端服务选项，选择「微信云开发」。不需要覆盖本项目或生成模板。
4. 核对 `project.config.json` 的 `appid` 已变为你的真实 AppID。
5. 项目配置已指定 `miniprogramRoot: miniprogram/` 和 `cloudfunctionRoot: cloudfunctions/`，正常会显示这两个目录。

建议调试基础库选开发者工具当前支持的稳定版本，至少支持 `wx.chooseMedia`。本项目没有小程序端 npm 依赖，不需要执行「构建 npm」。

## 三、开通云开发环境

1. 点击开发者工具顶部「云开发」，按提示开通并创建环境。
2. 本项目使用微信 `wx.cloud` 接入及**文档型 / NoSQL 数据库**。如果账号提供多种数据库模式，请选兼容该数据库 API 的环境，不要直接改用 PostgreSQL。
3. 复制完整的**环境 ID**，不是显示名称。
4. 编辑 `miniprogram/config.js`：

```javascript
module.exports = {
  envId: '你的真实云环境ID',
  title: '最新图片'
};
```

5. 在 `cloudfunctions` 目录的右键菜单中，如有「当前环境」，选中同一个环境。

开通前查看控制台实际套餐和计费说明，按需要设置费用提醒。这里不承诺免费额度或固定月费。

## 四、初始化数据库并配置权限

### 4.1 创建集合与记录

进入云开发控制台 → 数据库，创建集合：

```text
image_board
```

在集合中「添加记录」，切换到 JSON 模式，粘贴以下内容并保存（同样内容位于 `deploy/initial-record.json`）：

```json
{
  "_id": "current",
  "version": 0
}
```

`version` 必须是数字，`_id` 必须是 `current`。初始记录只需要这两个字段；不要手动填写空字符串 `fileID`，部分控制台编辑器会提示「Key 或 Value 不能为空」。未设置 `fileID` 时页面会显示「图片即将发布」，首次发布成功后云函数会自动写入 `fileID` 和 `updatedAt`。这条记录只在首次部署时创建，日常换图不要重置它。

### 4.2 数据库权限

将 `image_board` 集合设置为**仅管理端可读写**。若使用自定义安全规则，粘贴：

```json
{ "read": false, "write": false }
```

模板在 `deploy/database.rules.json`。这里的「管理端」指云函数 / 控制台，不是客户端管理页面。小程序的所有读写都通过云函数执行。

### 4.3 云存储权限

本项目通过微信原生文件通道上传，再由云函数核验文件和发布身份。**云存储不要照搬数据库的全禁写规则**，否则管理员也无法从小程序上传。

按当前环境实际支持的能力处理：

- **当前试用环境不能自定义规则：** 暂保留「仅创建者可读写」。无需执行第六节的复制自定义规则步骤。普通用户页面没有上传入口，发布仍由云函数管理员名单控制；但这一存储规则不能保证底层只有业务管理员可以创建文件。严格限制上传的要求尚未落实，不能把这项写成已验收通过。
- **环境支持自定义规则：** 完成第六节身份绑定后，使用管理页复制规则或 `deploy/storage.rules.json` 模板，限定管理员 OpenID 向 `uploads/` 写入。复制按钮生成单人规则；多管理员需统一维护名单，不能逐人覆盖。

「创建者」指每个文件的创建者，不是小程序账号的拥有者。图片访问链接由云函数生成；需用另一个微信账号验证普通用户查看。详见[架构文档](项目架构.md)及[官方基础权限说明](https://docs.cloudbase.net/storage/data-permission)。

修改规则后等待生效再验收。请勿为解决报错把数据库或存储改成「所有人可写」。[官方存储规则说明](https://docs.cloudbase.net/en/storage/security-rules)指出客户端规则不会限制服务端 SDK，规则变更可能需要 1–3 分钟生效。

## 五、部署云函数

1. 在左侧文件树展开 `cloudfunctions`。
2. 右键 **`imageBoard`**，选择「上传并部署：云端安装依赖（不上传 node_modules）」或同义入口。函数名要保持为 `imageBoard`。
3. 等待依赖安装和部署成功。函数使用固定版本 `wx-server-sdk@4.0.2`，无需在本机安装 npm。
4. 进入云开发控制台 → 云函数 → `imageBoard` → 配置，将超时时间设为 **60 秒**，内存可从 **256MB** 开始。运行时选择控制台支持的 Node.js 稳定版本，建议 Node.js 18 或更高。
5. 如果控制台提供云函数调用权限，保留允许本小程序微信身份调用的设置。发布操作还会在函数内部核验管理员身份，不能把整个函数设为「只有云控制台管理员可调用」，否则普通用户也无法看图。
6. 本项目通过小程序 `wx.cloud.callFunction` 调用，无需开启 HTTP 访问或配置 HTTP 触发器。

不要把 `ADMIN_OPENIDS` 写在前端页面或 `miniprogram/config.js`。下一步将在云端配置。

## 六、绑定你自己的微信为管理员

1. 点击电脑上微信开发者工具顶部「编译」，模拟器打开首页；不是寻找一个叫“编译管理页”的页面。尚未发布图片时显示「图片即将发布」，已有图片则显示当前图片。
2. 点击「预览」，用你以后要管理图片的微信扫码，在**手机真机**中打开。
3. 点击首页底部「管理入口」。首次会显示「当前微信没有发布权限」。这是预期行为。
4. 点击「复制我的 OpenID」。这个标识对应**当前微信在这个小程序中的身份**，不是微信号，也不是 AppID。
5. 回到电脑，打开云开发控制台 → 云函数 → `imageBoard` → 配置 / 环境变量，新增：

| 变量名 | 变量值 |
| --- | --- |
| `ADMIN_OPENIDS` | 第 4 步复制的完整 OpenID |

6. 保存配置，按界面提示使配置生效。如果工具要求更新函数，则重新部署并核对环境变量仍保留。
7. 手机管理页点击「重新验证权限」。现在应显示「已验证 · 管理员」和选图、发布按钮。
8. **仅在环境支持自定义规则时执行：** 在小程序管理页点击「首次部署：复制我的云存储权限规则」，打开云开发控制台 → 云存储 → 权限设置 → 自定义安全规则，粘贴并保存。当前试用环境不支持时跳过，按 4.3 保留「仅创建者可读写」。单管理员规则示例：

```json
{
  "read": false,
  "write": "auth.openid == '这里填你刚复制的OpenID' && /^uploads\\//.test(resource.path)"
}
```

9. 若修改了规则，等待生效再选图发布。数据库继续保持仅管理端可读写。使用自定义存储规则时，管理员名单与规则是两处配置，更换或移除管理员需要同步修改。试用环境的创建者规则不随 `ADMIN_OPENIDS` 改变。

需求是只有你有修改权限，所以默认只填你自己的一个 OpenID。以后确需多个管理员，值可用英文逗号分隔：`openidA,openidB`。移除某个 OpenID 并使配置生效后，该微信就不能继续发布；服务端每次发布都会重新校验身份。

如果拿开发者工具模拟器复制的 OpenID，务必核对它和实际管理用手机页面显示的一致。发布权限不自动等于微信公众平台里的「管理员」角色，而是由这里的名单明确指定。

## 七、发布第一张图片

1. 管理页点击「从相册或相机选择」，选择 JPG / PNG / WebP，文件不超过 **2MB**。
2. 检查预览图片。选图本身不会改变用户当前看到的内容。
3. 点击「确认并发布」，在确认框中点击「确认发布」。
4. 等待提示「发布成功」，核对「当前发布」区域的新图与更新时间。
5. 点击「返回展示页」，应显示同一张图片及北京时间。

大图请先压缩，HEIC / GIF 等请先转换为受支持的静态图片。如果微信提示隐私或相册 / 相机权限问题，先按提示授权并检查小程序后台的实际隐私接口声明。

如果显示连接异常或「发布结果暂未确认」，先刷新当前图片和版本确认是否已经成功。网络超时并不必然表示发布失败，程序不会自动重复提交。

新版分别显示「正在上传图片」及进度、「图片已上传，正在确认发布」「正在确认当前图片」。原生上传最多等待 60 秒、发布调用最多等待 45 秒、后续确认查询最多等待 20 秒。超过对应上限会退出等待并显示错误提示。云函数日志包含每个数据库 / 存储阶段的开始、完成、失败及请求 ID。排查方法见[项目架构文档](项目架构.md)第八节。

## 八、真机验收

用自己的微信和另一个已添加为体验成员的普通微信各验收一次：

- [ ] 自己能进入管理页面，普通微信只能看到无发布权限提示。
- [ ] 自己发布图片 A，普通微信打开首页能看到 A 和最后更新时间。
- [ ] 自己替换成图片 B，普通微信下拉刷新能看到 B。
- [ ] 普通微信退出后重新打开、或从后台切回展示页，能获取 B。
- [ ] 点击图片可放大，长图按宽度完整展示，不强制裁剪。
- [ ] 断网加载会显示失败和重试，不把旧图标成最新。
- [ ] 普通用户对数据库的客户端直写被拒绝。
- [ ] 若启用管理员专用存储规则，验证非管理员上传被拒绝；当前创建者规则不具备此保证，此项记为暂未实现。
- [ ] 即使普通微信直接调用 `publish`，云函数返回 `FORBIDDEN`，不会改变当前展示图片。

开发者工具控制台可用以下只读检查验证当前身份：

```javascript
wx.cloud.callFunction({
  name: 'imageBoard',
  data: { action: 'identity' }
}).then(console.log);
```

普通微信的拒绝测试可用下列代码：服务端应先校验身份，返回 `FORBIDDEN`。

```javascript
wx.cloud.callFunction({
  name: 'imageBoard',
  data: { action: 'publish', expectedVersion: 0, fileID: '' }
}).then(console.log);
```

这些调用必须在该微信登录的真实小程序环境中执行，不要用云控制台手动伪造身份验收。

## 九、体验版与正式版发布

### 9.1 先区分几个概念

| 名称 | 用途 | 如何获得 |
| --- | --- | --- |
| 本地编译 | 在开发者工具模拟器运行代码 | 工具顶部「编译」 |
| 手机预览 | 开发期间验证当前本地代码 | 工具「预览」生成二维码，用有权限的微信扫码 |
| 体验版 | 给有体验权限的人员测试 | 上传代码，在公众平台将开发版本设为体验版 |
| 正式版 / 线上版 | 对外提供服务 | 提交审核，通过后完成发布 |
| 云开发试用环境 | 后端资源套餐，涉及用量、期限、功能 | 云开发控制台管理，与代码体验版不是同一概念 |

体验版不是公开正式版，访问者需要体验权限；正式版需通过微信审核。参见[腾讯官方发布说明中的版本区别](https://free-plat-test.qcloudcdn.com/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/App-Publishing/Mini-Program)。该参考页的 WorkBuddy 发布入口不适用于本项目；下述操作使用微信开发者工具和公众平台。菜单名称以账号当前界面为准。

### 9.2 上传并设置体验版

1. 微信开发者工具打开 **`D:\wechat-image-board`**，核对 AppID 和 `miniprogram/config.js` 的环境 ID。先完成前述函数部署、初始数据和管理员配置；已有数据不要重新初始化。
2. 在工具里「编译」，再「预览」，用手机验证展示和发布。确认即将上传的代码无报错。**编译不会自动上传代码，也不会自动部署云函数。**
3. 点击开发者工具顶部 / 右上角「上传」（窗口窄时查看工具栏更多菜单）。填写代码版本如 `1.0.0`，备注如“单图展示、管理员换图，体验验证”，确认并等待上传成功。没有上传权限时，由公众平台管理员在成员管理中给当前微信相应开发权限。
4. 浏览器登录[微信公众平台](https://mp.weixin.qq.com/)，选择与项目 AppID 相同的小程序账号，进入「管理 → 版本管理」或「开发管理 → 版本管理」对应入口。
5. 在「开发版本」找到刚上传的版本，核对版本号、上传时间与备注，点击该版本操作菜单中的「设为体验版」。取得体验版二维码。若找不到版本，先核对账号 AppID 和上传结果。
6. 到「成员管理 / 成员设置 → 体验成员」，添加测试人员的微信号，按平台提示确认。**此处使用微信号；业务管理员配置使用 OpenID，两者不同。** 名额及授权方式以后台显示为准。
7. 让体验成员用自己的微信扫描体验版二维码。如果提示没有权限，核对扫码微信是否为已添加的成员，不要改数据库权限解决。
8. 选一名普通体验成员，按第八节验证看图和无发布权限。体验成员不会自动成为图片管理员。需要其管理图片时，再按第六节将其本小程序 OpenID 加入 `ADMIN_OPENIDS`。
9. 修复代码后重新上传一个可区分的版本（如 `1.0.1`），重新确认体验版指向该版本，并让测试者退出后重进验收。不要只更新本地编译就认为体验版已更新。

**同一环境的数据会共享：** 当前代码没有自动区分开发、体验、正式环境。体验版管理员成功换图，也会改变连接同一云环境的正式版展示。上线后需要独立测试时，应另建测试环境并配置对应函数、数据、权限；发布正式代码前核对生产环境 ID。

### 9.3 提交审核并发布正式版

1. **确认账号可正式发布。** 用正式注册的小程序账号，按公众平台要求完善名称、头像、简介、服务类目、资质、备案和用户隐私保护指引。图片实际内容应与类目和用途匹配；账号审核条件以后台为准，不承诺一定通过。
2. **核对后端可持续使用。** 查看云环境有效期、资源配额、套餐能力和费用提醒；小程序审核通过不等于试用云环境会自动续期。确认现有存储权限限制，严格“只有管理员可上传”目前仍未落实，不要宣称已完成。
3. **准备真实验收内容。** 当前图片应能正常显示，不能只有空态或测试报错。管理页选择相册 / 相机的用途按实际接口及后台检测填写隐私声明。本程序不主动收集昵称、头像或手机号；云函数使用 OpenID 判断发布身份。
4. **确定最终代码版本。** 若与验收过的体验版相同，可使用该开发版本；有任何前端修改则重新上传并验收。云函数改动单独部署，确认前后端兼容。
5. **提交审核。** 公众平台「版本管理 → 开发版本」找到目标版本，点击「提交审核」，按表单填写类目、功能页面与审核说明。展示页路径为 `pages/index/index`，管理页为 `pages/admin/admin`。
6. 审核说明可以按实际用途填写：“首页展示管理员发布的最新图片及更新时间，点击可放大；普通用户无需额外账号密码。管理入口仅对服务端名单中的指定微信身份开放，用于更换展示内容。”如平台要求补充审核访问条件，按其具体要求提供，不要把后台直接改成所有人可发布。
7. 查看「审核版本」进度。被退回时阅读具体原因，涉及代码则修改、重新上传、重新提交；涉及资料则按后台提示补充。不要将“已提交审核”视为“已上线”。
8. 审核通过后，在对应版本点击「发布 / 全量发布」并完成平台要求的确认。若界面提供自动发布或灰度选项，先明确所选方式；本指南按审核通过后手动发布说明。
9. 确认目标版本已出现在「线上版本」。在公众平台的小程序码 / 基本设置等入口下载**正式版小程序码**，再分发给用户。不要把开发预览码或体验版二维码当正式入口。
10. 用一个未添加为体验成员的微信扫描正式版码，验证图片显示、时间、放大和刷新；再用管理员微信验证换图。普通用户无需被加入体验成员即可使用已公开发布的正式版，仍受平台实际访问限制约束。

本指南不表示已代替用户完成上传、备案、审核或上线；实际状态以公众平台版本管理为准。

### 9.4 上线后更新什么、怎么更新

| 更新内容 | 操作 |
| --- | --- |
| 日常换图片 | 手机 → 管理入口 → 选图 → 发布；不改代码包，无需为每次换图重走代码审核，内容仍须符合平台规则 |
| 页面、样式、标题、前端逻辑 | 修改 D 盘源码 → 编译 / 真机验收 → 上传新版本 → 审核 → 发布 |
| 云函数逻辑 / 依赖 | 单独部署云函数；共用环境的所有代码版本都会受影响，先验证兼容性 |
| 新增 / 移除业务管理员 | 更新 `ADMIN_OPENIDS` 并使其生效；如使用自定义存储规则，名单也需同步 |

上线验收记录建议包含代码版本号、Git 提交、云环境、部署时间和验证结果。云数据不随 Git 自动备份。需要回退图片，按第十一节重新发布旧原图；回退代码不能自动回退云数据或云函数。

## 十、常见问题

| 现象 | 优先检查 |
| --- | --- |
| 提示填写环境 ID | 修改 `miniprogram/config.js`，填完整环境 ID 后重新编译 |
| 云函数找不到 / 连接失败 | AppID、环境 ID、`cloudfunctions` 当前环境和函数部署目标是否一致，函数名是否为 `imageBoard` |
| 提示创建初始记录 | 集合是否叫 `image_board`，是否有 `_id: current` 的记录 |
| 添加记录提示 Key 或 Value 不能为空 | 使用上面的两字段初始记录，省略空的 `fileID` 和未设置的更新时间 |
| 发布提示版本无效 | `version` 是否是数字，是否误改了初始记录 |
| 本人没有发布权限 | 手机当前 OpenID 是否与云函数环境变量一致，配置是否生效，是否填到了错误环境 |
| 普通用户也无法看图 | 云函数调用权限是否允许本小程序用户，是否误把函数调用权限设为仅管理端 |
| 图片不可访问 | 当前记录的 fileID 对应文件是否还存在，函数是否在正确云环境中生成链接；看云函数日志 |
| 选图失败 | 检查真实文件格式、2MB 限制、微信版本、隐私授权及手机相册 / 相机权限 |
| 上传超时 | 先刷新确认发布结果，再检查网络、函数超时时间和日志；较大图片先压缩 |
| STORAGE_PERMISSION / 云存储拒绝上传 | 按 4.3 核对实际权限；支持自定义时核对规则与 OpenID，当前试用环境保留创建者权限。不要误用数据库全禁写规则 |
| INVALID_FILE / 只能发布本人图片 | 两端代码是否都更新为原生上传版，文件是否属于同一环境和本人 uploads 目录 |
| 一直停在正在发布 | 核对开发工具打开 D 盘最新代码，按架构文档定位上传或 publish 阶段；云函数代码修改后须重新部署 |
| 提示图片已被更新 | 同一时间有另一个发布操作成功。刷新确认最新图片，再重新选图发布 |
| 换图后用户停留页面没变 | 下拉刷新，或离开并重新进入展示页；此版本未做持续实时推送 |
| 本地没有 npm | 直接使用微信工具「云端安装依赖」；本地测试只需要 Node.js |

## 十一、维护、清理与回退

### 旧文件与费用

只有确认发布后才开始上传，单纯选图预览不上传。每次上传成功都会保存新的 `uploads/<OpenID>/` 文件，旧文件不会自动删除；历史实现可能在 `published/` 留有文件。数据库只维护当前图片的一条记录，不保存每张图的历史列表。详见[项目架构](项目架构.md)第三、四节。保留旧文件可避免已经打开的页面因立即删图而失效，但长期更新会占用存储。

建议低频手动清理：先从数据库 `image_board/current` 复制当前 `fileID`，再到云存储确认文件；**保留当前 fileID 对应文件及最近一段时间的旧文件**，只删除已确认不再引用的历史文件。清理过程中先暂停人工发布操作，并在删除前再次核对当前记录。不要直接清空 `uploads/` 或 `published/` 目录。

失败或结果不确定的上传也可能遗留文件，可按同样方式核对。控制台设置费用提醒，关注图片访问流量、函数调用和存储用量，具体价格看当前账号计费页。

### 回退图片

日常回退最简单的做法：管理员重新选择之前的原图并发布。系统会生成新的版本和更新时间，不必手动改数据库。
