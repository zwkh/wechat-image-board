# 微信小程序：一张图片，统一更新

已经包含可导入微信开发者工具的完整原生小程序和云函数。后台管理入口就在小程序里，使用你的微信身份验证，无需记密码，也无需单独搭建管理网站。

## 你要的功能

- 用户打开首页：显示当前发布的一张图片，下面显示最后更新时间（北京时间）。
- 点击图片：放大查看，长按可使用微信图片菜单。
- 管理员打开「管理入口」：选择图片 → 预览 → 确认发布。
- 替换图片后，用户重新打开、从后台切回首页或下拉刷新，会获取最新图片。
- 只有云函数环境变量中指定的微信 OpenID 可以发布；普通用户即使直接调用发布接口也会被拒绝。

当前页面持续停留期间不会自动推送换图。图片上限为 **2MB**，支持 JPG、PNG、WebP。未发布时显示空态，加载失败时显示重试入口。

## 方案与文件

采用 **微信原生小程序 + 微信云开发（云函数、文档数据库、云存储）**。小程序既有用户展示页，也有管理员页面；真正的后台是云函数。使用微信云开发接入，不需要自行部署服务器或购买业务域名。

```text
微信用户 → 展示页 → imageBoard 云函数 → 当前图片记录 → 云存储图片
管理员   → 管理页 → 微信身份校验 → 上传新文件 → 更新当前记录
```

| 文件 | 用途 |
| --- | --- |
| `project.config.json` | 微信开发者工具项目配置，填写 AppID |
| `miniprogram/config.js` | 填写云环境 ID、首页标题 |
| `miniprogram/pages/index/` | 用户展示页 |
| `miniprogram/pages/admin/` | 管理员选图、发布页面 |
| `cloudfunctions/imageBoard/` | 服务端身份校验、读取、发布 |
| `deploy/` | 初始数据库记录与权限规则 |
| `docs/部署指南.md` | 从注册到发布的逐步操作 |
| `tests/` | 服务端与页面逻辑的自动化测试 |

## 部署速览

1. 注册微信小程序，取得真正的 **AppID**，安装微信开发者工具。
2. 导入本项目根目录，填写 AppID；开通微信云开发环境，使用**文档型数据库**。
3. 在 `miniprogram/config.js` 填入环境 ID。
4. 创建数据库集合 `image_board`，添加 `deploy/initial-record.json` 中的初始记录。数据库、云存储均设置为**仅管理端可读写**。
5. 右键 `cloudfunctions/imageBoard`，选择**上传并部署：云端安装依赖**，然后在云函数配置中将超时时间调整为 **60 秒**。
6. 编译 → 用你自己的微信预览 → 管理入口 → 复制自己的 OpenID。在云函数环境变量中新增 `ADMIN_OPENIDS=你的OpenID` 并保存生效。回到管理页「重新验证权限」，就能发布第一张图片。
7. 真机验收后，在开发者工具上传代码，到微信公众平台提交审核，审核通过后发布。按平台要求完成备案、类目及隐私保护指引等资料。

详细图文式操作说明、常见报错和验收清单见 [部署指南](docs/部署指南.md)。代码当前使用占位 AppID、环境 ID，**还没有部署到你的微信账号**。

## 日常操作

手机打开小程序 → 管理入口 → 选择图片 → 确认并发布。以后更换图片属于更新云端内容，不需要重新上传小程序代码；内容应符合所选类目和微信平台规则。

想改首页标题，编辑 `miniprogram/config.js` 中的 `title`。导航栏名称分别在页面的 `index.json`、`admin.json` 中配置；修改小程序代码后需要重新上传和发布。

## 验证

安装 Node.js 后，在项目根目录执行（不需要安装测试依赖）：

```powershell
node scripts/check.js
node --test tests/service.test.js tests/frontend.test.js
```

测试覆盖权限拒绝、伪造身份、文件格式与大小限制、并发发布冲突、发布结果不确定、重新打开获取新图、加载失败和北京时间显示。测试使用模拟云服务，不等于微信真机或真实云环境验收；部署后仍需按指南验证权限和完整上传链路。

## 运行说明

- 更新时间由服务端生成，客户端不能指定。
- 每次发布使用新文件路径，避免替换同一路径导致旧图缓存。
- 更新记录使用版本条件进行原子更新，同时发布时只允许一个请求成功。
- 上传与数据库写入不能跨服务原子提交。如果网络异常，界面会刷新确认结果，不会自动重复发布；未确认的文件会保留，避免误删已经发布的图片。
- 旧图片保留在云存储中，避免已经打开的页面失效。维护者可按部署指南定期清理，长期使用会产生存储占用。
- 云开发可能产生资源费用，以控制台当前套餐、资源用量及计费说明为准。
